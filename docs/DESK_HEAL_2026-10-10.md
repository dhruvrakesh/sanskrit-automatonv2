## 3. What changed

### DESK_HEAL_2026_10_10 (`scripts\patch_desk_heal_2026_10_10.py`)

**`scripts/dashboard.py`. It takes effect when the dashboard is restarted, and only when idle.**
- `/api/status` builds one answer at a time. Callers that arrive meanwhile share that answer, and it
  is kept 10 s (`STATUS_TTL_S`).
- These clear it: a job that ends, an import, and `?fresh=1`. An answer begun before a job ended is
  never kept (a generation counter).
- `/api/health` is new. It answers from memory, in milliseconds, for the hub and the scripts:
  `{ok, mark, pid, up_s, jobs: {count, active, queued, running}}`.
- **The Library:**
  - Under each text it says what the last translation run did, when that run could not do the work:
    - held by the debris guard, with the OCR consensus command and `SA_ALLOW_DEBRIS=1`;
    - nothing left to translate;
    - nearly all of what is left is below the OCR quality bar.
  - These notes come from `data/jobs.jsonl`. A later run that translated replaces an older note,
    including a pipeline run whose summary shows a Translate stage.
  - *Finish EN* and *Add Hindi* follow the run they start. They show *queued: after the running one*,
    then *translating...*, then the outcome: *held*, *nothing to do*, *done: N of M*, *failed* or
    *stopped*. The outcome is also shown as a toast.

**`scripts/dashboard_static.html`. The page takes it when it is reloaded.**
- **Usage** reads cost_tracker's summary as it is: calls, passages, characters sent and received, the
  cost by engine, and the last 10 paid calls.
- **History:**
  - It tells *held* and *nothing* apart from *fail* and *stopped*.
  - Click a row to see the run's last six lines.
  - History and Usage load when opened, with no "Click Reload".
- **The Queue** list also takes the texts from the last status, and opens on the text being
  translated.
- **Status reads:**
  - The page never starts a second status read while one is running. A call that comes meanwhile
    runs once, after it.
  - *Refresh*, and the refresh after an import, ask for a fresh answer.
  - The first empty state says *Loading the documents...*, not *No documents in inbox*.

**`scripts/maintenance_runner.ps1`. It takes effect at the task's next run.**
- An OCR job no longer holds maintenance. Any other job still does.
- Between its steps, maintenance looks again. If a database writer has started, it logs *SKIP rest
  after step ...* and leaves the rest for the next tick. A writer can be the OCR's own ingest and
  translation stage, or a run started by hand.
- A writer that starts inside a step waits on SQLite's lock: WAL mode, busy_timeout 30-60 s. This was
  already true of a run started by hand during maintenance.

### HUB_V2_2026_10_10 (`scripts\patch_hub_v2_2026_10_10.py`)

It installs `docs/hub/HUB_V2_2026-10-10/hub.py` and `hub.html` into the hub's folder. It replaces
only the v1 it was written against (md5-guarded), and adds section U4 to the hub's README.

**Health checks:**
- v2 asks the dashboard `/api/health`, or `/api/jobs/running` on a dashboard from before
  DESK_HEAL_2026_10_10. It never asks `/api/status`, and its proxy no longer forwards it.
- One round of checks runs side by side, at most once every 8 s, however many hub pages are open.
  The page asks every 15 s.
- A dashboard that holds its port but answers slowly shows as *busy*, not down.

**Start:**
- *Start* runs `scripts\restart_dashboard.ps1`: no window, logs in `D:\backups\dashboard_logs`.
  Closing run.bat's window used to end the dashboard and every run it had started.
- Start appears only when the dashboard is down.

**The page, in three columns:**
- **This PC makes it:**
  - the translation engine: what runs and for how long, and the spend cap;
  - the database: texts, verses, English and Hindi, names, stories, pictures, graphic novels;
  - the brain: passage vectors, how many English verses are left to embed (as `build_embeddings.py`
    picks them), when maintenance last kept it current, why it skipped, and a run that never
    finished.
- **The cloud carries it:**
  - the mirror to Supabase: the last run, the last good run, groups equal and different, a final
    check that could not run;
  - the pictures on Drive;
  - the Corner desk: rounds, requests and mail;
  - each from its own log, with the scheduled task's next run.
- **The site serves it:** srangam.nartiang.org, with links into the working corpus: Library, Stories,
  Names, Pictures, Graphic novels, the Corner, the Corner's Sync, Learn, Published texts, Admin.

**Reading and the rest:**
- The database is counted read-only (`mode=ro`) in the background, every 10 min. A request never
  queries it.
- The scheduled tasks are asked every 5 min (`Get-ScheduledTaskInfo`).
- Panchang, Booksmith and the wisdomlib crawl are as before.

### What stays where

**This PC:**
- translation and OCR;
- the database: `data\context.db` is created and upserted here only;
- the Gemini brain's vectors are made here (3,072 dimensions) by the maintenance task.

**The cloud:**
- the mirror (`corpus_sync.py`, every 2 h) carries the database to Supabase in full and checks it,
  group by group;
- the vectors travel with it, cut to 1,536 dimensions;
- the pictures go to Drive after each mirror run;
- the Corner's requests come back through `corner_worker.py`.

**The site:** it reads the mirror and never writes the database.

## 4. Apply

The order matters. Each step can stand alone.

1. **The hub, now:** `python scripts\patch_hub_v2_2026_10_10.py --check`, then without `--check`.
   Close the hub's console window and start `start-hub.bat`. Against the dashboard as it runs now,
   the hub uses `/api/jobs/running`.
2. **The dashboard files:** `python scripts\patch_desk_heal_2026_10_10.py --check`, then without
   `--check`. This writes the three files. The running dashboard keeps its old code in memory.
   - Reload the dashboard page (Ctrl+F5) and the Library: Usage, History, the Queue and the refresh
     work at once.
   - Its new endpoints (`/api/health`, the shared status, the Library's notes and its following
     button) come with a restart.
   - Maintenance takes it at its next run (every 3 h).
3. **The dashboard, only when idle.** `scripts\restart_dashboard.ps1` refuses while jobs run.
   - **To keep the OCR running:** wait for it to end, about a day. Maintenance no longer waits for it.
   - **To restart now:** press Pause All. The OCR resumes from the missing pages: Queue, Import & Run,
     or `/api/queue/run` for the same text. Then run `restart_dashboard.ps1`.
