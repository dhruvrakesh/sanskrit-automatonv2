# L2: what a first visit downloads, and two surgical cuts (2026-10-09)

Marker LOAD_L2_2026_10_09. Measured on a production build of Srangam main 84409ca, in a copy of the tree. The method: a Rollup plugin listing every chunk and every module of the entry with its import chain, then headless Chromium against `vite preview`. The full measurement, with every table and the diffs of all five proposals, was kept with the build; the figures below are from it.

## 1. What a visitor downloads

**Sizes are in bytes.** Vite's build report prints the entry as about 491-499 kB. That figure counts characters; the file is 607 kB, because the article data carries nine scripts.

**The entry chunk: 607.5 kB, 173.5 kB gzip.**
- **About 28% (175 kB): `src/data/articles/meta.ts`** (titles and descriptions of every article in 9 languages). It is there because `App.tsx` imports Home eagerly. Home and its subtree hold about 40% of the entry.
- **The header and footer (`Layout`): about 66 kB.** Language menu, mobile sheet, popover, search.
- **All nine UI languages: about 64 kB.** A visitor uses one.
- **The two toast hosts (Radix toaster and sonner): about 48 kB.**
- **By origin:** 40% npm packages, 60% site code.

**The home page `/`:**
- 5 files before first paint: 1156.8 kB, 311.1 kB gzip (the entry, vendor-react, vendor-supabase, vendor-i18n, the CSS).
- Then a 547.9 kB (132.4 kB gzip) chunk, `cultural-terms`, on every visit. `GeomythologySection` wrapped the word "samudra" in `CulturalTermTooltip`, which downloads the whole terms dataset to look the word up. "samudra" is in none of the `cultural-terms*.ts` files, so the tooltip only ever rendered a plain span.
- That chunk was 29% of a home visit.

**The working corpus `/corpus`:** the same 5 files plus 6 CorpusHome chunks, 326.6 kB gzip before its content.

## 2. What this release changes (`scripts/patch_srangam_load_l2_2026_10_09.py`)

| | Change | Saving | Risk |
|---|---|---|---|
| P4 | `GeomythologySection.tsx`: "samudra" is the plain `<span>` it always rendered as | the 548 kB (132 kB gzip) request on every home visit | none visible. An article card whose description carries a `{{cultural:...}}` term still loads the dataset when it shows that term |
| P3 | `App.tsx`: the two toast hosts load right after the first render, inside a Suspense | the entry -46.7 kB (-13.1 kB gzip), on every route | a sonner toast raised in the first ~100 ms of a page load could be lost (only admin pages use sonner). Radix toasts are kept in memory and shown |

**Measured on the patched tree:**
- The entry is 560.6 kB (159.7 kB gzip), against 607.3 kB (173.4 kB gzip).
- Typecheck is clean.
- Tests: the full suite passes but for the 3 known environment-only failures. `src/__tests__/load-l2.test.ts` adds 3 tests (including that "samudra" is still in no terms file).
