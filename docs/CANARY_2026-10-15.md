## 4. RUN_FIX_2026_10_15 (scholar_translate.py)

**A critic whose answer cannot be read.** 3 of 29 critiques (in 25 sentences) came back not as JSON (17.4, 20.6,
20.8). Now:
- `parse_json` reads the first whole JSON object in an answer, whatever follows it (`first_object`, at most 20 "{"
  tried). The old greedy match then follows, as before. Words after the JSON, or a "}" in them, no longer lose the
  answer.
- A Claude critic that does not answer in JSON is asked once more, as a draft already was (not after a refusal). A
  second ask costs about a critic's call.
- An answer still not JSON is kept in `unparsed_<doc>.jsonl` beside the run's log (data\scholar). The file records the
  kind, how the answer ended, its length, and its first and last 300 characters. It needs a log folder and never raises.
- The row's doubts then say "the critic's answer could not be read", adding "(it is kept in unparsed_<doc>.jsonl
  beside the run's log)" when it was. The status stays flagged, unless the audit reads that verse.

**A dashboard pipeline past its ingest.** pipeline_queue.py runs OCR, ingest, translate and export, in that order.
- Its translate stage is translate_passages.py, the same as a dashboard "translate" job, which is quiet already
  (COST_TRUTH_2026_10_15). It writes only the working English (the passages' translation columns, translations_l10n,
  translation_history, the FTS) and never a passage's text, so it never changes a src_hash.
- Its export stage writes HTML.
- `busy_with` therefore leaves out a running pipeline job whose output (`/api/job/<id>`, read-only, no proxy, six
  seconds) has the stage header `  Translate <doc>` or `  Export <doc>`. pipeline_queue.py prints that header before
  each stage, and the dashboard runs python unbuffered.
- A queued pipeline, one still at its OCR or ingest, or a dashboard that does not answer stops the run, as before.

**Tests.**

- `test_claude_engine_2026_10_15`: a critic is asked once more.
