3. HOW A ROUND IS BUILT (the house style)
- Stage the files to change from the PC, keep a base copy and a new copy, edit the new copy.
- Build the patcher with handover\mkpatcher.py (it needs mkpatch.py beside it):
    build(out_path, MARK, tag, docstring, [files], {file: marker it must already carry}, base=<base dir>, new=<new dir>)
  Anchored edits, all or nothing, idempotent by MARK (MARK must be new in every file), .bak_<tag>_<date> copies.
- A test module per patch in tests\ (test_<name>_<date>.py) with a replay of the patcher on the .bak copies. An older
  test that replays an older patcher on a file you changed needs a "came after" fallback to your .bak_<tag>_* copy.
- A docs patch each round (patch_docsNNN_<date>.py): a new section of ASKS (a table: Date | Ask | Done (evidence) |
  Left), a section of STATE, the commands in RUNBOOK; and its test (rows counted, key phrases, no placeholder such as
  an angle-bracketed word). A commit message file COMMIT_MSG_<tag>_<date>.txt ending with the attribution lines the
  session gives.
- Srangam changes travel as a kit in the automaton repo: docs\srangam\<KIT>\ (the files) and
  scripts\patch_srangam_<kit>_<date>.py (md5-guarded replace of the exact version main has; new files). Then
  npm run typecheck, npx vitest run, npm run build; git add the files by name; commit; push; Publish in Lovable.
  Publish does not deploy an edge function: ask Lovable in its chat to deploy it as it is in the repository.
- Testing without touching the PC's database: copy the repo's scripts, tests and docs to the VM's own disk
  (handover\refresh_o.py), apply the patchers there, run the suite in pieces (handover\runner.py <copy> <out.jsonl>
  <seconds>, repeated until "left 0": a shell call ends at 180 s and kills background jobs). Srangam the same
  (handover\sync_srx.py), vitest in shards (--shard=1/6 ...) with VITE_SUPABASE_URL=http://localhost:54321 and
  VITE_SUPABASE_PUBLISHABLE_KEY=test-not-a-real-key. Site SQL is tested on a PostgreSQL 16 set up in the cloud workspace.
- Traps met: a heredoc turns \uXXXX escapes into letters (run handover\asciify.py on a .py after writing it); on
  Windows a test must close its sqlite connections before tearDown (WinError 32); the VM has no .env, the PC has.
